Claude Code 定價分析報告

研究背景

本報告針對 Claude Code 的定價機制進行深入分析，特別關注 prompt caching 功能中的 cache read 和 cache write 收費問題，以及不同服務路徑下的計價差異。

核心發現

1. Prompt Caching 收費確認

重要結論：快取讀取（cache read）和快取寫入（cache write）都會被收費，且會包含在總成本（Total Cost）中。

Anthropic 直接 API 計價結構：

項目 計價倍數 說明
Cache Write (5分鐘) 1.25x 基礎 input token 價格的 1.25 倍
Cache Write (1小時) 2x 基礎 input token 價格的 2 倍
Cache Read 0.1x 基礎 input token 價格的 0.1 倍（90% 折扣）

2. 快取儲存位置

快取儲存在 Anthropic 的伺服器端，不是本地儲存。特性包括：

  • 組織隔離：不同組織間的快取完全隔離
  • 精確匹配：需要 100% 相同的 prompt 片段才能命中
  • 生存時間：預設 5 分鐘，可選 1 小時

3. 不同服務路徑的計價差異

架構 A：Claude Code → Anthropic API 直接

使用 Anthropic 官方計價規則： - Cache write: 1.25x (5分鐘) 或 2x (1小時) - Cache read: 0.1x - 標準 input/output tokens

架構 B：Claude Code → AWS Gateway → AWS Bedrock → Anthropic

使用 AWS Bedrock 計價規則： - Cache read: 高達 90% 折扣 - Cache write: 可能高於標準費率 - 標準 input/output tokens
關鍵差異：AWS Bedrock 使用彈性折扣制度，而非 Anthropic 直接 API 的固定倍數制度。

4. 官方文件參考

  • Anthropic 官方文件： Claude Pricing Documentation
  • AWS Bedrock 官方文件： Prompt caching for faster model inference
  • AWS Bedrock 定價： Amazon Bedrock Pricing

5. Total Cost 計算邏輯

無論使用哪種架構，Claude Code 顯示的 "Total Cost" 都會包含：

  • Input tokens 費用
  • Output tokens 費用
  • Cache read tokens 費用
  • Cache write tokens 費用

最終顯示的總成本會根據對應的服務路徑計價規則進行計算。

總結

由於計費規則複雜且不確定，所以我們最終比較基準應該以顯示的 Total Cost 為準。
